  <name>Task 2: Fix NTP clock resync after WiFi reconnect</name>
  <files>hardware/pantalla/include/wifi_manager.h</files>
  <read_first>hardware/pantalla/include/wifi_manager.h</read_first>
  <action>
    **wifi_manager.h** (per D-10 — NTP resync):

    The bug: On line 119, after WiFi reconnect, `timeClient.forceUpdate()` is called but `setTime(timeClient.getEpochTime())` is NOT called. This means the TimeLib internal clock drifts after WiFi reconnects, causing incorrect timestamps in photo filenames and display clock.

    Fix in the `WIFI_ST_WAITING_RETRY` case, inside the `if (WiFi.status() == WL_CONNECTED)` block (around line 119):

    Change:
    ```cpp
    timeClient.forceUpdate();
    ```

    To:
    ```cpp
    timeClient.forceUpdate();
    setTime(timeClient.getEpochTime());
    ```

    This mirrors what setup() does on initial boot (line 299 of main.cpp: `setTime(timeClient.getEpochTime())`).

    Note: `setTime()` is from TimeLib.h which is included transitively via main.cpp. Since wifi_manager.h is a header included from main.cpp, it has access to `setTime()` from the TimeLib already included there. Add `#include <TimeLib.h>` at the top of wifi_manager.h (after the existing includes) to make the dependency explicit and not rely on include order.
  </action>
  <verify>
    <automated>cd /datos/almacen_fp/hardware/pantalla && grep -A2 "forceUpdate" include/wifi_manager.h | grep -q "setTime" && echo "PASS" || echo "FAIL"</automated>
  </verify>
  <acceptance_criteria>
    - wifi_manager.h contains `setTime(timeClient.getEpochTime())` on the line immediately after `timeClient.forceUpdate()`
    - wifi_manager.h contains `#include <TimeLib.h>` near the top includes
    - The existing `wifiJustReconnected = true;` line is preserved (not removed)
  </acceptance_criteria>
  <done>After WiFi reconnect, NTP time is synced back to TimeLib so photo timestamps and display clock remain accurate</done>
